kind: **BREAKING**: `fireline-synth` requires `unpopped-vocab` 0.45.12 (was 0.43.2)
---
`fireline-synth` now depends on `unpopped-vocab` 0.45.12, the newest published (crates.io, read 2026-11-13). The published `fireline-synth` 0.1.0 pins 0.43.2, so a consumer that has moved to Unpopped 0.45.12 builds two copies of the vocabulary and `OperandDesc` (and `ArchSku`, `TargetId`, `ElementKind`) are then two different types at the seam; this repin gives one copy. **Why BREAKING:** the vocabulary types appear in `fireline-synth`'s public signatures (`JitRequest` and the `Synthesizer` trait use `OperandDesc`, `ArchSku` and `TargetId`), so their type identity moves with the pin: a consumer on `unpopped-vocab` 0.43.x can no longer pass them to this version. Pre-1.0 that is the second number: release as **`fireline-synth` 0.2.0** (the PM allocates; the crate version is not edited here). No source change was needed: the workspace builds, `cargo test --workspace --locked` passes (3 synth tests, the `synth_hello_world` example runs), clippy `-D warnings` and `cargo doc` are clean, there is no example-name collision, and `cargo tree -i unpopped-vocab` shows the single copy 0.45.12. `Cargo.lock` changes only the `unpopped-vocab` entry (version and checksum). The stale "requires 0.43.2" line in `docs/PUBLISHING.md` is updated. Not verified: whether Unpopped's own types changed shape between 0.43.2 and 0.45.12 (the build and tests passing is the check made; no consumer was built here).
